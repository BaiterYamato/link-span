## Resultado

- **A página de itens do NEI entrou na DLL e o menu do jogo a usa.** Não é um menu novo: são três
  funções do kaleido do host desviadas para a versão do fork (`fork/kaleido_glue.cpp`):
  `KaleidoScope_DrawItemSelect`, `KaleidoScope_SetupItemEquip` e `KaleidoScope_UpdateItemEquip`. O
  resto do menu — mapa, equipamento, quest, fundo, setas de página — continua sendo o do host, que é
  o "sem substituir o menu inteiro quando não necessário" do plano.
- **Duas páginas, 48 slots.** Página 0 são os 24 slots vanilla; página 1 são os slots 24..47 do NEI,
  guardados no `gNeiSave` (NEI-012) e não no `SaveContext`. A terceira página, das máscaras de MM,
  fica desligada nesta prova (`gMods.MmMasks.InventoryEnabled=0`) porque exige `mm.o2r`.
- **Navegação, cursor, nome e equipar funcionam na página do NEI**: o cursor anda na grade, o painel
  de nome acompanha o slot e um item da página vai para um botão C pela mesma tecla de sempre.
- **Troca de página é o BTN_L** (`ExtInv_SwitchPage`, dentro do `DrawItemSelect` do fork), a não ser
  que `gEnhancements.NGCKaleidoSwitcher` esteja ligado, quando passa a ser o BTN_Z.
- **Nada disso mexeu no `soh.exe`.** O layout id continua `ce528052` e o pacote continua preso ao
  mesmo fingerprint de host.

### Máquina de extração, que é o que tornou isso possível sem tocar o host

- `fork/extract_additions.py` ganhou **sobreposição**: uma semente com `>` na frente no `extract.txt`
  é copiada do fork mesmo quando o host também tem a função, porque a DLL desvia a do host para ela.
  Antes, um nome presente no host virava import e a versão do fork era descartada.
- O mesmo script agora lê o `soh.symbols`: função que o host tem mas que o **LTCG inlinou** não tem
  endereço para o escape hatch resolver, então é copiada do fork em vez de virar import. Foram cinco
  (`KaleidoScope_SetCursorVtx`, `IsItemCycling`, `ItemInSlotUsesAmmo`, `CanMaskSelect`,
  `KaleidoScope_ResetItemCycling`).
- `fork/sync.py` alinha as redeclarações locais de array de dado do host pela declaração do próprio
  host (22 nesta árvore). Sem isso, `extern void* gItemIcons[];` escrito dentro do fork virava um
  ponteiro para array **incompleto** e brigava com o `[158]` do `variables.h` (C2369). Apagar a linha
  não servia: às vezes ela é a única declaração que o arquivo enxerga (`gEquipAgeReqs`).
- `--exclui` tira do resultado um `#include` de unity do fork. O `z_kaleido_item.c` inclui
  `extended_inventory.c`, que agora tem unidade própria na DLL (`fork/inventory_unit.c`).
- `soh/expansions/sw97` entrou nas árvores copiadas: o `extended_inventory.c` inclui o
  `sw97_config.h`.

### O que ficou em `fork/kaleido_shim.c`, e por quê

- `OTRGetDimensionFromLeftEdge`, `OTRGetDimensionFromRightEdge` e `OTRGetRectDimensionFromRightEdge`
  são funções de uma linha do `OTRGlobals.cpp` que o LTCG inlinou e sumiram do `soh.symbols`. A conta
  delas é a mesma sobre `OTRGetAspectRatio()`, esse resolvido, então a DLL refaz a conta em vez de
  stubar — o resultado posiciona o HUD em tela larga.
- `ExtButton_GetItem/SetItem/ClearItem`: o fork guarda o id u16 de item de mod em
  `gSaveContext.ship.extButtons`, um campo que **ele acrescentou ao `z64save.h`**. Mexer nesse header
  mudaria o layout id da rodada, então a DLL fica com a própria tabela. Ver Pendências.

## Riscos

- **Os três desvios substituem, não embrulham.** Qualquer outro mod que desvie as mesmas funções
  entra em conflito: o `install_patch` recusa o segundo patch no mesmo endereço com `LIMIT`, e o
  kaleido do NEI fica desligado com o motivo no `stats`.
- **`gDeveloperTools.DebugEnabled=1` rouba o BTN_L dentro da pausa** para o editor de save do SoH.
  Com ele ligado a troca de página não acontece — foi assim que a primeira prova falhou.
- O pacote segue preso ao `soh.exe` da rodada: o escape hatch resolve 302 funções e 50 dados pelo
  `soh.symbols`, e a cópia de teste precisa ter esse arquivo ao lado do executável.
- O `Page2Relayout_Heal` limpa células cujo subsistema é stub. Conforme o NEI-008 em diante trouxer
  esses subsistemas, o número de células ocupadas sobe.

## Pendências

- **Ícones da página do NEI saem errados.** O `ExtInv_GetItemIcon` aponta para texturas do bundle de
  assets do fork, que não é redistribuível e não está no pacote; o resource manager desenha lixo no
  lugar. A grade, o cursor, o nome e o equipar estão certos — é o **NEI-007** que fecha isso.
- **Item de id u16 num botão C não entra no save.** O `extButtons` do fork não existe no `SaveContext`
  deste host e a DLL guarda a tabela em memória (`fork/kaleido_shim.c`). Persistir exige mexer no
  `z64save.h`, o que custa o layout id; entra na próxima rodada que já for trocá-lo, junto das duas
  dívidas do NEI-012.
- **Só a página de itens foi desviada.** O `z_kaleido_scope_PAL.c` do fork também mexe em
  `KaleidoScope_Update`, `DrawPages`, `UpdateNamePanel`, `DrawInfoPanel`, `InitVertices`,
  `SetDefaultCursor` e `func_80823A0C` — refinamentos (cursor padrão na célula certa, painel de
  informação, vértices das páginas extras). Ficaram de fora deste recorte.
- **Os cinco pontos de ciclagem** (`KaleidoScope_HandleItemCycles`, `DrawItemCycles`,
  `DrawItemCycleExtras`, `HandleItemCycleExtras`, `ResetItemCycling`) estão compilados na DLL, mas
  não desviados: as chamadas do PAL do host continuam indo para a versão do host, então as rodas de
  ciclagem na página do NEI não rodam.
- **`inv_fill` é instrumento de teste, não aquisição.** A hotkey no `core-main.lua` sai quando o
  coremod for empacotado para valer (NEI-016); a aquisição de verdade é o get-item do fork (NEI-008).
- Review humana.
